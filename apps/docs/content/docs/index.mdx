Welcome to **next-nest-monorepo** — a production-grade, enterprise-ready SaaS platform template built with modern technologies.

## What is next-nest-monorepo?

A comprehensive, fully-featured SaaS foundation that includes:

✅ **Multi-organization support** with RBAC
✅ **Built-in authentication** (email, OAuth, magic links, 2FA)
✅ **Stripe billing integration** (subscriptions, invoices, webhooks)
✅ **Global multi-language support** with i18n
✅ **Modern tech stack** (Next.js 16, React 19, TypeScript, Tailwind CSS)
✅ **Production-ready** security, performance, and scalability
✅ **Comprehensive documentation** and best practices

## Getting Started in 3 Steps

### 1. Clone & Install
```bash
git clone <repo-url>
cd next-nest-monorepo
pnpm install
```

### 2. Setup Environment
```bash
# Create apps/web/.env.local
DATABASE_URL=postgresql://...
BETTER_AUTH_SECRET=your-secret
```

### 3. Run Dev Server
```bash
pnpm dev
# Main app: http://localhost:3000
# Docs: http://localhost:3004
```

## Common Tasks

### Creating a New Feature
1. Create route under `/apps/web/app/[locale]/(app)/`
2. Add authorization checks
3. Use components from `@repo/design-system`
4. Style with Tailwind CSS

### Adding Database Models
1. Update `packages/database/prisma/schema.prisma`
2. Run `pnpm migrate`
3. Use generated types in application

### Deploying to Production
1. Push code to main branch
2. Connect to Vercel
3. Set environment variables
4. Deploy

See [Deployment](/docs/getting-started/deployment) for detailed guide.

## Architecture Highlights

### Monorepo Structure
- **apps/** — Independent applications (web, docs, email, storybook)
- **packages/** — Shared code (auth, database, design-system, payment)
- **Turborepo** — Orchestrates building and testing

### Route Organization
```
/[locale]/
├── (app)/           ← Authenticated app
│   ├── [orgSlug]/   ← Organization routes
│   └── account/     ← User account routes
├── (frontier)/      ← Public/marketing
└── auth/            ← Authentication
```

### Multi-Tenancy
- Organizations are the root tenant
- Users belong to organizations with roles
- Data is scoped by organization
- Role-based permissions control access
