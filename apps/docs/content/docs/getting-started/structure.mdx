## Apps Breakdown

### Web App (`apps/web`)

Main SaaS application with authentication, multi-org support, and billing.

**Key directories:**
- `app/[locale]/(app)/` — Authenticated routes
- `app/[locale]/(frontier)/` — Public/marketing pages
- `app/[locale]/auth/` — Authentication flows
- `app/api/` — Backend API routes
- `lib/` — Shared utilities, hooks, helpers
- `components/` — Shared React components

**Important files:**
- `proxy.ts` — Edge proxy for route protection (Next.js 16 replacement for middleware.ts)
- `layout.tsx` — Root layout with locale handling
- `next.config.mjs` — Next.js configuration
- `.env.local` — Environment variables

### Docs App (`apps/docs`)

Fumadocs-powered documentation site with MDX support.

**Key directories:**
- `content/docs/` — MDX documentation files
- `app/(home)/` — Landing page
- `app/docs/` — Documentation pages

**Important files:**
- `source.config.ts` — Fumadocs MDX configuration
- `mdx-components.tsx` — Custom MDX components

### Email App (`apps/email`)

A thin React Email **preview runner** (`email dev`). It has no local `app/` or `emails/` — the templates live in `@repo/email` (`packages/email/templates/`), which this app points at.

### Storybook

Component library and design system documentation with Storybook.

**Key directories:**
- `stories/` — Component stories

### Studio

Wrapper around Prisma Studio for database inspection and management.

## Packages Breakdown

### Core Packages

#### `@repo/auth`
Better Auth configuration with:
- Authentication methods (email/password, OAuth, magic links, 2FA)
- Dual RBAC: platform-level admin roles + organization-scoped roles
- Client hooks and server instance
- Session management

#### `@repo/database`
Prisma ORM with:
- Data models in `schema.prisma`
- Generated Prisma client in `generated/client/`
- Seed script for development data
- Migration management via `prisma.config.ts`

#### `@repo/design-system`
UI component library with:
- shadcn/ui base components
- Theme provider (light/dark mode)
- Tailwind CSS utilities

#### `@repo/payment`
Stripe integration featuring:
- Subscription plan definitions (Free, Pro, Enterprise)
- Plan utilities and comparison functions
- Pricing constants and billing intervals

### Supporting Packages

#### `@repo/utils`
Shared utility functions for:
- Date constants (durations, intervals)
- Payment constants (plan names, statuses)
- Slug generation and validation

#### `@repo/logger`
Structured logging with:
- Server-side Pino logger (`@repo/logger/server`)
- Client-side logger (`@repo/logger/client`)

#### `@repo/email`
React Email templates (in `templates/`) — email verification, password changed, magic link, org invitations, new-device login, account deleted/locked, and more — sent via Resend (prod) or Nodemailer → MailDev (dev).

#### `@repo/seo`
SEO utilities for:
- Metadata generation
- Sitemap generation
- JSON-LD structured data

#### `@repo/internationalization`
i18n configuration with:
- Locale definitions
- Translation keys
- Locale-specific routing

#### `@repo/storage`
File storage integration with:
- Local and S3 storage providers
- File upload helpers

#### `@repo/typescript-config`
Shared TypeScript configuration for type consistency.

## Route Structure in Web App

### Authenticated Routes (`/[locale]/(app)/`)

```
/[locale]/(app)/
├── [orgSlug]/          # Organization-scoped routes
│   ├── page.tsx        # Organization dashboard
│   ├── settings/       # Organization settings
│   ├── billing/        # Billing management
│   ├── members/        # Member management
│   └── checkout/       # Checkout flow
├── account/            # User account routes (no org required)
│   ├── profile/        # Profile settings
│   ├── security/       # Security settings (sessions, 2FA)
│   ├── danger/         # Account deletion
│   └── new-org/        # Create organization
├── invite/             # Organization invitation handling
└── org/                # Organization selection
```

### Public Routes (`/[locale]/(frontier)/`)

```
/[locale]/(frontier)/
├── page.tsx           # Home/landing page (Hero, Features, Pricing blocks)
└── components/        # Home-page section blocks
```

> There is no separate `/pricing` route — pricing is a block on the home page.

### Authentication Routes (`/[locale]/auth/`)

Each route is a Server-Component `page.tsx` plus a `components/` folder of `"use client"` logic; the form UI lives in `@repo/design-system` (`components/molecules/auth/`).

```
/[locale]/auth/
├── sign-in/          # page.tsx + components/{password,magic-link,email-otp}-sign-in.tsx
├── sign-up/          # page.tsx + components/password-sign-up.tsx
├── forgot-password/  # page.tsx + components/
├── reset-password/   # page.tsx + components/
├── verify-email/     # page.tsx + components/
├── 2fa/              # page.tsx + components/
└── magic-link/       # page.tsx + components/
```

### API Routes (`/api/`)

```
/api/
├── auth/[...all]/    # Better Auth handler (incl. Stripe webhooks via @better-auth/stripe)
├── health/           # Health check (database + auth)
├── upload/           # File uploads
└── user/activity/    # User activity tracking
```

> Billing (checkout / change-plan) and invitations are handled by **server actions**
> (`(app)/[orgSlug]/.../actions.ts`), not REST routes. Stripe webhooks arrive at
> `/api/auth/stripe/webhook` through the `@better-auth/stripe` plugin.

## Import Path Aliases

### Web App (`apps/web/tsconfig.json`)

```typescript
"@/*" → apps/web/         // Web-specific files
"@repo/*" → packages/     // Shared packages
```

### Other Apps/Packages

```typescript
"@/*" → apps/[app-name]/  // App-specific files
"@repo/*" → packages/     // Shared packages
```

## File Organization Best Practices

### By Feature
```
app/[locale]/(app)/[orgSlug]/members/
├── page.tsx              # Page component
├── layout.tsx            # Layout
├── components/           # Feature-specific components
│   ├── member-list.tsx
│   ├── member-form.tsx
│   └── ...
├── actions.ts            # Server actions
└── ...
```

### Component Locations

- **UI components**: `packages/design-system/components/ui/`
- **Feature components**: `app/[feature]/components/`
- **Shared app components**: `apps/web/components/`

### Utility Locations

- **Database**: `packages/database/`
- **Auth**: `packages/auth/`
- **Shared app utilities**: `apps/web/lib/`
- **Feature utilities**: `app/[feature]/lib/`

## Monorepo Benefits

- **Code reuse** — Shared packages across apps
- **Unified tooling** — Single build system via Turborepo
- **Dependency management** — pnpm workspaces
- **Consistent linting** — One Biome config
- **Efficient CI/CD** — Only build what changed
- **Shared types** — TypeScript types across apps
