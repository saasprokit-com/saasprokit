## Deployment Overview

The monorepo is designed for deployment to modern cloud platforms. Each app can be deployed independently or together.

## Platform Options

### Recommended: Vercel

**Best for**: Most SaaS applications, especially those prioritizing ease of use.

#### Deployment Steps

1. **Connect your repository**
   ```bash
   vercel login
   vercel link
   ```

2. **Configure environment variables**
   - Go to Vercel project settings
   - Add all variables from `.env.local`

3. **Configure build settings**
   - Build command: `pnpm build`
   - Output directory: `.next`
   - Install command: `pnpm install --frozen-lockfile`

4. **Deploy**
   ```bash
   vercel deploy --prod
   ```

#### Environment Variables for Vercel

```bash
# Database
DATABASE_URL=postgresql://...

# Better Auth
BETTER_AUTH_SECRET=your-secret
BETTER_AUTH_URL=https://yourdomain.com
NEXT_PUBLIC_APP_URL=https://yourdomain.com

# Stripe
STRIPE_SECRET_KEY=sk_live_...
STRIPE_WEBHOOK_SECRET=whsec_live_...
STRIPE_PRO_PRICE_ID_MONTHLY=price_...
STRIPE_PRO_PRICE_ID_ANNUAL=price_...
STRIPE_ENTERPRISE_PRICE_ID_MONTHLY=price_...
STRIPE_ENTERPRISE_PRICE_ID_ANNUAL=price_...

# OAuth
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GITHUB_CLIENT_ID=...
GITHUB_CLIENT_SECRET=...

# Email
RESEND_API_KEY=...
EMAIL_FROM=noreply@yourdomain.com

# Storage
STORAGE_PROVIDER=s3
S3_BUCKET=your-bucket
S3_REGION=us-east-1
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
```

### Alternative Platforms

- **Railway** — Good for full-stack apps with database hosting
- **Render** — Good alternative with auto-deploy
- **AWS Amplify** — For AWS-centric deployments

## Multi-App Deployment Strategy

### Option 1: Single Deployment (Recommended for MVP)

Deploy the web app on Vercel:

```
Main app: yourdomain.com → Vercel
Docs: docs.yourdomain.com → Vercel (optional)
```

### Option 2: Separate Deployments (For Scale)

```
Main App (Web): yourdomain.com → Vercel
Docs: docs.yourdomain.com → Vercel/Netlify
Email Preview: internal-only → Not deployed
Storybook: storybook.yourdomain.com → Chromatic
```

## Pre-Deployment Checklist

### Code Quality
- [ ] No TypeScript errors: `pnpm --filter web typecheck`
- [ ] Lint checks passing: `pnpm check`
- [ ] Tests passing: `pnpm test`

### Configuration
- [ ] All environment variables set in deployment platform
- [ ] `BETTER_AUTH_URL` matches production domain
- [ ] `NEXT_PUBLIC_APP_URL` matches production domain
- [ ] Database migrations applied: `pnpm migrate`

### Security
- [ ] `BETTER_AUTH_SECRET` is strong (32+ characters, random)
- [ ] Database credentials are not in code
- [ ] OAuth credentials configured for production
- [ ] Stripe webhook secret from production account

## Database Deployment

### PostgreSQL Hosting Options

#### Neon (Recommended for Serverless)
```bash
DATABASE_URL=postgresql://user:password@ep-*.neon.tech/database
```

#### AWS RDS
```bash
DATABASE_URL=postgresql://admin:password@rds-endpoint.amazonaws.com:5432/database
```

### Initial Database Setup

1. **Run migrations**
   ```bash
   pnpm migrate
   ```

2. **Verify schema**
   ```bash
   npx prisma studio
   ```

3. **Seed data (development only)**
   ```bash
   pnpm --filter @repo/database db:seed
   ```

## Post-Deployment Steps

### 1. Verify Deployment

```bash
# Check health endpoint
curl https://yourdomain.com/api/health
```

### 2. Configure Stripe Webhooks

Add webhook endpoint in Stripe Dashboard:

```
Endpoint URL: https://yourdomain.com/api/stripe/webhook

Events to subscribe to:
- customer.subscription.created
- customer.subscription.updated
- customer.subscription.deleted
- invoice.payment_succeeded
- invoice.payment_failed
- checkout.session.completed
```

### 3. Set Up DNS

```bash
# Point your domain to Vercel
# Add CNAME record:
www.yourdomain.com CNAME: yourdomain.vercel.app
```

HTTPS is automatic on Vercel and most modern platforms.

### 4. Set Up Custom Domain

```bash
vercel domains add yourdomain.com
vercel domains verify yourdomain.com
```

## Scaling Considerations

### Database
- Use connection pooling (Prisma Accelerate for serverless)
- Add read replicas for heavy read workloads
- Monitor slow queries

### Application
- Vercel Edge Network handles CDN and caching automatically
- Implement Redis caching for frequently accessed data as needed
- Monitor with Sentry and Pino structured logging

## Rollback Strategy

### Using Vercel

```bash
# View previous deployments
vercel deployments

# Rollback to previous deployment
vercel rollback
```

### Manual Rollback

1. Revert to previous commit
2. Revert database migrations if needed (`npx prisma migrate resolve`)
3. Redeploy

## Troubleshooting

### Build Fails
- Check that all environment variables are set
- Verify database connection string is correct
- Check TypeScript errors: `pnpm --filter web typecheck`

### Database Connection Issues
- Verify connection string format
- Check that PostgreSQL instance is running and accessible
- For serverless, ensure connection pooling is configured

### Stripe Webhooks Not Working
- Verify webhook endpoint URL matches: `/api/stripe/webhook`
- Check that `STRIPE_WEBHOOK_SECRET` matches the webhook signing secret
- Test with Stripe CLI: `stripe listen --forward-to localhost:3000/api/stripe/webhook`
