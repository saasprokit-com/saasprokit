## Overview

This project uses environment variables for configuration across different apps. Copy the `.env.example` file to `.env.local` in each app directory and fill in your values.

## Web App (`apps/web`)

### App URLs

```bash
# Public URLs for the application
NEXT_PUBLIC_APP_URL="http://localhost:3000"
NEXT_PUBLIC_DOCS_URL="http://localhost:3004"
```

| Variable | Description | Required |
|----------|-------------|----------|
| `NEXT_PUBLIC_APP_URL` | Main application URL | Yes |
| `NEXT_PUBLIC_DOCS_URL` | Documentation site URL | No |

### Database

```bash
# Neon PostgreSQL connection string
DATABASE_URL="postgresql://user:password@host:5432/database?sslmode=require"
```

| Variable | Description | Required |
|----------|-------------|----------|
| `DATABASE_URL` | PostgreSQL connection string (Neon recommended) | Yes |

### Authentication (Better Auth)

```bash
# Better Auth configuration
BETTER_AUTH_SECRET="your-super-secret-key-at-least-32-characters"
BETTER_AUTH_URL="http://localhost:3000"
```

| Variable | Description | Required |
|----------|-------------|----------|
| `BETTER_AUTH_SECRET` | Secret key for signing tokens (min 32 chars) | Yes |
| `BETTER_AUTH_URL` | Base URL for auth callbacks | Yes |

<Callout type="warn">
Generate a secure secret using: `openssl rand -base64 32`
</Callout>

### OAuth Providers

#### Google OAuth

```bash
GOOGLE_CLIENT_ID=""
GOOGLE_CLIENT_SECRET=""
```

| Variable | Description | Required |
|----------|-------------|----------|
| `GOOGLE_CLIENT_ID` | Google OAuth client ID | No* |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret | No* |

Setup: [Google Cloud Console](https://console.cloud.google.com/apis/credentials)

1. Create a new OAuth 2.0 Client ID
2. Add authorized redirect URI: `{BETTER_AUTH_URL}/api/auth/callback/google`

#### GitHub OAuth

```bash
GITHUB_CLIENT_ID=""
GITHUB_CLIENT_SECRET=""
```

| Variable | Description | Required |
|----------|-------------|----------|
| `GITHUB_CLIENT_ID` | GitHub OAuth App client ID | No* |
| `GITHUB_CLIENT_SECRET` | GitHub OAuth App client secret | No* |

Setup: [GitHub Developer Settings](https://github.com/settings/developers)

1. Create a new OAuth App
2. Set Authorization callback URL: `{BETTER_AUTH_URL}/api/auth/callback/github`

<Callout>
*OAuth providers are optional but recommended for social login functionality.
</Callout>

### Stripe (Payments & Subscriptions)

```bash
STRIPE_SECRET_KEY=""
STRIPE_WEBHOOK_SECRET=""
STRIPE_PRO_PRICE_ID=""
STRIPE_ENTERPRISE_PRICE_ID=""
```

| Variable | Description | Required |
|----------|-------------|----------|
| `STRIPE_SECRET_KEY` | Stripe API secret key (starts with `sk_`) | No* |
| `STRIPE_WEBHOOK_SECRET` | Webhook signing secret (starts with `whsec_`) | No* |
| `STRIPE_PRO_PRICE_ID` | Price ID for pro plan | No* |
| `STRIPE_ENTERPRISE_PRICE_ID` | Price ID for enterprise plan | No* |

Setup: [Stripe Dashboard](https://dashboard.stripe.com)

1. Get API keys from Developers > API keys
2. Create Products and Prices in Product catalog
3. Set up webhook endpoint: `{NEXT_PUBLIC_APP_URL}/api/stripe/webhook`
4. Subscribe to events: `checkout.session.completed`, `customer.subscription.*`

<Callout>
*Stripe variables are only required if using payment/subscription features.
</Callout>

## Subscription Plans

The app supports three subscription tiers:

| Plan | Features | Organization Limit |
|------|----------|-------------------|
| **Free** | Basic access | Cannot create organizations |
| **Pro** | Full features | Up to 3 organizations |
| **Enterprise** | All features + priority support | Unlimited organizations |

## Security Best Practices

1. **Never commit `.env.local`** - It's already in `.gitignore`
2. **Use different secrets** for development and production
3. **Rotate secrets regularly** in production environments
4. **Use environment-specific values** - Don't reuse dev keys in production
5. **Validate required variables** - The app will fail to start if critical variables are missing
