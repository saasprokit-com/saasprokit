## Environment Variables

Configure your email provider using environment variables in your `.env` file.

### Common Variables

```bash
# Sender address for all outgoing emails
EMAIL_FROM="App Name <noreply@yourdomain.com>"

# Provider selection (optional - auto-detected if not set)
EMAIL_PROVIDER=resend|nodemailer
```

### Provider-Specific Variables

<Tabs items={['Resend (Production)', 'Nodemailer (Local/SMTP)']}>
  <Tab value="Resend (Production)">
    ```bash
    # Required for Resend
    RESEND_API_KEY=re_xxxxxxxxxxxxx
    ```

    Get your API key from the [Resend Dashboard](https://resend.com/api-keys).
  </Tab>
  <Tab value="Nodemailer (Local/SMTP)">
    ```bash
    # SMTP Configuration
    SMTP_HOST=localhost        # Default: localhost
    SMTP_PORT=1025             # Default: 1025 (Maildev)
    SMTP_SECURE=false          # Default: false
    SMTP_USER=                 # Optional - for authenticated SMTP
    SMTP_PASS=                 # Optional - for authenticated SMTP
    SMTP_POOL=false            # Default: false - enable connection pooling
    ```
  </Tab>
</Tabs>

## Provider Auto-Detection

The email package automatically selects the appropriate provider based on your environment:

| Condition | Selected Provider |
|-----------|-------------------|
| `EMAIL_PROVIDER` is set | Uses specified provider |
| `NODE_ENV=production` + `RESEND_API_KEY` present | Resend |
| `NODE_ENV=development` | Nodemailer |
| No configuration | Nodemailer (localhost:1025) |

<Callout type="info">
  Auto-detection means you can run locally without any configuration - emails will be sent to localhost:1025 where Maildev can catch them.
</Callout>

## Configuration Schema

The configuration is validated using Zod via `@t3-oss/env-nextjs`. Here's the real schema:

```typescript
// packages/email/keys.ts
import { createEnv } from '@t3-oss/env-nextjs';
import { z } from 'zod';

export const keys = () =>
  createEnv({
    server: {
      EMAIL_PROVIDER: z.enum(['resend', 'nodemailer']).optional(),
      EMAIL_FROM: z.string().default('App <noreply@localhost>'),

      // Resend
      RESEND_API_KEY: z.string().optional(),

      // SMTP/Nodemailer
      SMTP_HOST: z.string().default('localhost'),
      SMTP_PORT: z.coerce.number().default(1025),
      SMTP_SECURE: z.coerce.boolean().default(false), // custom string->bool transform, not z.coerce.boolean() directly (see source)
      SMTP_USER: z.string().optional(),
      SMTP_PASS: z.string().optional(),
      SMTP_POOL: z.coerce.boolean().default(false),
    },
    runtimeEnv: {
      EMAIL_PROVIDER: process.env.EMAIL_PROVIDER,
      EMAIL_FROM: process.env.EMAIL_FROM,
      RESEND_API_KEY: process.env.RESEND_API_KEY,
      SMTP_HOST: process.env.SMTP_HOST,
      SMTP_PORT: process.env.SMTP_PORT,
      SMTP_SECURE: process.env.SMTP_SECURE,
      SMTP_USER: process.env.SMTP_USER,
      SMTP_PASS: process.env.SMTP_PASS,
      SMTP_POOL: process.env.SMTP_POOL,
    },
  });
```

## Usage in Applications

<Callout type="info">
In `apps/web`, the auth-related templates (password reset, email verification, magic link, OTPs, org invitations) are **not** called directly from app routes or server actions — they're triggered by Better Auth plugin hooks in `packages/auth/server.ts` (e.g. `emailAndPassword.sendResetPassword`), and the subscription templates by `packages/auth/stripe-hooks.ts`. See [Configuration](/docs/authentication/configuration) for those hooks. Several other templates (welcome, account-deleted, role-changed, and others — see [Templates](/docs/email/templates)) are fully built but not currently called from anywhere; the example below shows the pattern for wiring one up yourself.
</Callout>

### Calling a send function directly

```typescript
'use server';

import { sendWelcomeEmail } from '@repo/email';

export async function onUserCreated(email: string, name: string) {
  await sendWelcomeEmail({ email, name });
}
```

## Verifying Setup

Check if your email configuration is working:

```typescript
import { getEmailProvider } from '@repo/email/providers';

// This will log which provider is being used
const provider = getEmailProvider();
console.log(`Using email provider: ${provider.name}`);
```

## Troubleshooting

### Common Issues

| Issue | Solution |
|-------|----------|
| "RESEND_API_KEY required" | Set the `RESEND_API_KEY` environment variable or switch to nodemailer |
| Connection refused on port 1025 | Start Maildev: `docker compose up maildev` |
| Emails not appearing | Check Maildev UI at http://localhost:1080 |
| Invalid sender address | Verify domain in Resend dashboard for production |

### Debug Mode

Enable debug logging by setting:

```bash
DEBUG=email:*
```
