## Overview

[Maildev](https://github.com/maildev/maildev) is a local SMTP server with a web interface for viewing and testing emails during development. It captures all emails sent via SMTP without actually delivering them.

### Benefits

- **No API keys needed** - Works completely offline
- **Instant feedback** - See emails immediately in the web UI
- **Full email inspection** - View HTML, plain text, headers, and raw source
- **Responsive testing** - Preview emails at different screen sizes
- **REST API** - Automate email testing in your test suite

## Maildev Web Interface

The web interface at http://localhost:1080 provides:

| Feature | Description |
|---------|-------------|
| **Inbox** | List of all captured emails |
| **HTML View** | Rendered HTML email |
| **Plain Text** | Plain text version |
| **Headers** | Email headers (From, To, Subject, etc.) |
| **Source** | Raw email source (RFC 822) |
| **Responsive Preview** | Resize viewport to test responsive design |

## Docker Compose Setup (already configured)

This repo's root `docker-compose.yml` already defines Maildev — you don't need to add it:

```yaml
maildev:
  image: maildev/maildev:latest
  container_name: maildev
  ports:
    - "1080:1080"  # Web UI
    - "1025:1025"  # SMTP
  environment:
    - MAILDEV_WEB_PORT=1080
    - MAILDEV_SMTP_PORT=1025
  restart: unless-stopped
  healthcheck:
    # 127.0.0.1, not localhost: the web UI binds IPv4-only, and localhost
    # resolves to ::1 inside the container, failing the check.
    test: ["CMD", "wget", "-q", "--spider", "http://127.0.0.1:1080"]
    interval: 30s
    timeout: 10s
    retries: 3
```

## Testing with Maildev REST API

Maildev provides a REST API for automated testing:

### Get All Emails

```bash
curl http://localhost:1080/email
```

### Get Specific Email

```bash
curl http://localhost:1080/email/{id}
```

### Delete All Emails

```bash
curl -X DELETE http://localhost:1080/email/all
```

### Example: E2E Test

This repo already has a Maildev REST API helper at `apps/web/e2e/helpers/maildev.ts` — use `clearInbox()`/`waitForEmail()` from there instead of reimplementing the polling/fetch logic:

```typescript
import { test, expect } from '@playwright/test';
import { clearInbox, waitForEmail } from '../helpers/maildev';

test('sends a verification email on sign-up', async ({ page }) => {
  await clearInbox();

  await page.goto('/auth/sign-up');
  await page.fill('[name="email"]', 'test@example.com');
  await page.fill('[name="password"]', 'password123');
  await page.click('button[type="submit"]');

  const email = await waitForEmail('test@example.com', {
    subjectContains: 'verify',
  });

  expect(email.to[0].address).toBe('test@example.com');
});
```

## Email Relay (Optional)

Maildev can relay selected emails to a real SMTP server for testing:

```bash
docker run -p 1080:1080 -p 1025:1025 \
  -e MAILDEV_OUTGOING_HOST=smtp.gmail.com \
  -e MAILDEV_OUTGOING_PORT=587 \
  -e MAILDEV_OUTGOING_USER=your-email@gmail.com \
  -e MAILDEV_OUTGOING_PASS=your-app-password \
  maildev/maildev
```

Then click "Relay" on any email in the web UI to send it to the real SMTP server.

<Callout type="warn">
  Only use relay for testing specific emails. Never relay sensitive or test data to real inboxes.
</Callout>

## Alternative: Ethereal Email

If you prefer a cloud-based solution, [Ethereal](https://ethereal.email) is a free SMTP service for testing:

```typescript
import nodemailer from 'nodemailer';

// Create test account
const testAccount = await nodemailer.createTestAccount();

// Configure transport
const transporter = nodemailer.createTransport({
  host: 'smtp.ethereal.email',
  port: 587,
  auth: {
    user: testAccount.user,
    pass: testAccount.pass,
  },
});

// View emails at: https://ethereal.email
```

<Callout type="info">
  Ethereal requires internet access and creates temporary accounts. Maildev is recommended for offline development.
</Callout>

## Troubleshooting

### Port Already in Use

```bash
# Find process using port 1025
lsof -i :1025

# Kill the process
kill -9 <PID>
```

### Emails Not Appearing

1. Verify Maildev is running: `docker ps` or check http://localhost:1080
2. Check your app is using port 1025: `EMAIL_PROVIDER=nodemailer SMTP_PORT=1025`
3. Look for errors in your app logs

### Connection Refused

```bash
# Check if Maildev is listening
nc -zv localhost 1025

# If using Docker, ensure ports are mapped
docker port maildev
```

### Docker Network Issues

If your app is also in Docker, use the service name instead of localhost:

```yaml
# docker-compose.yml
services:
  app:
    environment:
      - SMTP_HOST=maildev  # Use service name, not localhost
      - SMTP_PORT=1025
```
