title: Checkout Flow
description: How subscriptions are created, upgraded, downgraded, and canceled

## Checkout (New Subscription)

When a user upgrades from Free to a paid plan:

```
User clicks "Upgrade to Pro"
  ↓
UpgradeForm → startCheckoutAction (server action)
  ↓
Create/retrieve Stripe customer
  ↓
Create Stripe Checkout Session
  - mode: "subscription"
  - price ID based on plan + billing interval
  - metadata: organizationId, userId, planName, billingInterval
  - allow_promotion_codes: true
  - billing_address_collection: "required"
  ↓
Redirect to Stripe-hosted checkout page
  ↓
User completes payment on Stripe
  ↓
Webhook: checkout.session.completed
  - Sends "subscription started" email
  - Better Auth plugin syncs subscription to database
  ↓
Redirect to success URL
```

### Checkout Session Metadata

All checkout sessions include metadata for traceability:

```typescript
metadata: {
  organizationId: string;
  organizationSlug: string;
  organizationName: string;
  userId: string;
  planName: "pro" | "enterprise";
  billingInterval: "monthly" | "yearly";
}
```

This metadata is validated with Zod on the webhook side to ensure type safety.

### Server Action

The checkout is initiated via a server action in `apps/web/app/[locale]/(app)/[orgSlug]/billing/actions.ts`:

```typescript
"use server";

// startCheckoutAction:
// 1. Verify session & org membership
// 2. Validate input with checkoutRequestSchema
// 3. Create/retrieve Stripe customer
// 4. Create checkout session with metadata
// 5. Redirect to session.url
```

## Plan Upgrade

Upgrading from Pro to Enterprise (or changing billing interval) while already subscribed:

```
User selects new plan → changePlanAction (server action)
  ↓
Validate upgrade direction (comparePlans)
  ↓
Update Stripe subscription:
  - New price ID
  - proration_behavior: "create_prorations"
  - Updated metadata
  ↓
Update database subscription.plan
  ↓
Webhook: customer.subscription.updated
  - Detects upgrade via tier comparison
  - Sends "subscription upgraded" email
```

Prorations are created automatically — Stripe calculates the credit for unused time on the old plan and charges the difference for the new plan.

## Plan Downgrade

Downgrading to a lower tier:

```
User selects lower plan → changePlanAction (server action)
  ↓
Validate downgrade direction
  ↓
Run guardDowngrade() — check member count + storage usage
  ↓
If blocked: return error with reason
If OK: update Stripe subscription with new price
  ↓
Update database subscription.plan
  ↓
Webhook: customer.subscription.updated
  - Detects downgrade via tier comparison
  - Sends "subscription downgraded" email
```

### Downgrade to Free

Downgrading to the Free plan is handled differently — it returns `action: "cancel"` and directs the user to use the cancellation flow instead, since Free has no Stripe subscription.

## Cancellation

```
User clicks "Cancel Subscription"
  ↓
Confirmation dialog (AlertDialog)
  ↓
useCancel hook → subscription.cancel()
  ↓
Sets cancelAtPeriodEnd on Stripe (access continues until period end)
  ↓
Webhook: customer.subscription.deleted
  - Sends cancellation email with access-until date
  - Includes link to billing page for reactivation
```

Cancellation is **not immediate** — the subscription remains active until the current billing period ends.

## Billing Portal

Users can manage payment methods and view invoices through Stripe's hosted billing portal:

```
"Manage Billing" button → openBillingPortalAction
  ↓
Retrieve stripeCustomerId from subscription
  ↓
Create Stripe billing portal session
  ↓
Redirect to portal URL
```

## Authorization

Only organization **owners** and **admins** can manage billing. This is enforced at two levels:

1. **Better Auth plugin** — `authorizeReference` callback checks org role
2. **Billing page** — Checks `"update"` permission on organization before rendering

```typescript
// packages/auth/server.ts
authorizeReference: async ({ user, referenceId, action }) => {
  // action: "upgrade-subscription" | "cancel-subscription" | "billing-portal"
  return canManageBilling(user.id, referenceId);
};
```
