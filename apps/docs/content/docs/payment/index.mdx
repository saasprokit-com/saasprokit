The project uses **Stripe** for all payment processing, integrated through the **Better Auth Stripe plugin**. Billing is scoped to organizations — each organization has its own subscription.

## Architecture

```
packages/
├── payment/              # Plan definitions, guards, helpers, hooks
├── utils/payment.ts      # Constants, pricing, Stripe price mapping
└── auth/
    ├── server.ts         # Better Auth Stripe plugin config
    └── stripe-hooks.ts   # Subscription lifecycle email hooks

apps/web/
├── lib/billing/
│   ├── stripe.ts                 # Stripe client singleton
│   └── subscription-queries.ts   # Database queries for subscriptions/usage
├── app/api/auth/[...all]/        # Better Auth catch-all (handles Stripe webhooks)
└── app/[locale]/(app)/[orgSlug]/billing/
    ├── page.tsx         # Billing dashboard
    ├── actions.ts       # Server actions (checkout, portal, plan change)
    ├── schemas.ts       # Zod validation
    └── components/      # UI components
```

## Key Concepts

### Organization-Scoped Billing

Every subscription is tied to an organization via `referenceId`. Users don't have individual subscriptions — they manage billing through their organization.

### Webhook Handling

Stripe webhooks are delivered to **`/api/auth/stripe/webhook`** (handled by Better Auth's Stripe plugin via its catch-all route). The plugin verifies signatures, syncs subscription state to the database, and invokes lifecycle hooks defined in `packages/auth/stripe-hooks.ts`:

- `onSubscriptionComplete` → welcome email (first checkout)
- `onSubscriptionUpdate` → upgrade or downgrade email
- `onSubscriptionDeleted` → cancellation email
- `onEvent` → renewal email (on `invoice.paid` with `billing_reason: "subscription_cycle"`) and dunning email (on `invoice.payment_failed`)

### Three-Tier Subscription Model

| Plan | Monthly | Annual | Members | Storage |
|------|---------|--------|---------|---------|
| Free | $0 | $0 | 1 | 100 MB |
| Pro | $19 | $190 | 10 | 5 GB |
| Enterprise | $49 | $490 | 50 | 50 GB |

```bash
STRIPE_PRO_PRICE_ID_MONTHLY=""          # Pro monthly price ID
STRIPE_PRO_PRICE_ID_ANNUAL=""           # Pro annual price ID
STRIPE_ENTERPRISE_PRICE_ID_MONTHLY=""   # Enterprise monthly price ID
STRIPE_ENTERPRISE_PRICE_ID_ANNUAL=""    # Enterprise annual price ID
```

## Data Models

### Subscription

```prisma
model Subscription {
  id                   String    @id @default(cuid())
  plan                 String    // "free", "pro", "enterprise"
  referenceId          String    // organizationId
  stripeCustomerId     String?
  stripeSubscriptionId String?
  status               String?   @default("incomplete")
  periodStart          DateTime?
  periodEnd            DateTime?
  cancelAtPeriodEnd    Boolean?  @default(false)
  seats                Int?
}
```
