title: Two-Factor Authentication
description: The TOTP second factor, the onTwoFactorRedirect hook, the /auth/2fa step, and how it gates session creation
---

When a user has two-factor enabled, a correct password (or other first factor) is **not enough** to mint a session. Better Auth returns a "two-factor required" result, the client redirects to `/auth/2fa`, and only a valid second factor completes the sign-in.

## Server configuration

The `twoFactor()` plugin (`packages/auth/server.ts`) is configured with both a TOTP authenticator and an email-OTP fallback:

```ts
twoFactor({
  issuer: env.NEXT_PUBLIC_APP_NAME,        // shown in authenticator apps
  otpOptions: {
    async sendOTP({ user, otp }) {
      await sendTwoFactorOTPEmail({ email: user.email, otp, expiresInMinutes: OTP_EXPIRES_IN_MINUTES });
    },
    period: TWO_FACTOR_OTP_PERIOD_MINUTES,  // 5
    digits: TWO_FACTOR_DIGITS,              // 6
  },
}),
```

Per-user 2FA state is persisted in the `TwoFactor` model (`secret`, `backupCodes`) and flagged on `User.twoFactorEnabled`. The `/two-factor/*` endpoints are rate-limited to 5 requests/minute.

## Enabling 2FA

Generating the TOTP secret, showing the QR code, and issuing backup codes happens in **account settings** (`/account/security`), not on the auth pages — a user must already be signed in to turn it on. This section covers the *challenge* side: proving the second factor at sign-in.

## The redirect hook

The client never has to detect the 2FA branch manually. `twoFactorClient` (`packages/auth/client.ts`) registers a redirect callback that Better Auth invokes whenever a flow needs a second factor:

```ts
twoFactorClient({
  onTwoFactorRedirect() {
    if (typeof window !== "undefined") {
      window.location.href = "/auth/2fa";
    }
  },
})
```

So `signIn.email` (or any first factor) on a 2FA-enabled account triggers a full-page navigation to `/auth/2fa`.

## The /auth/2fa page

`2fa/components/two-factor-form.tsx` dispatches `verifyTwoFactorAction` and, on success, lands the user at `/org`:

```tsx
const [state, formAction, isPending] = useActionState(
  verifyTwoFactorAction,
  initialFormState
);

onSubmit={form.handleSubmit((values) =>
  startTransition(() => formAction(values))
)}

// success effect
router.push(PAGE_ROUTES.ORG);
router.refresh();

// actions.ts — the verification itself runs server-side
await auth.api.verifyTOTP({ headers: await headers(), body: { code } });
```

<Callout type="warn">
The page only wires **TOTP**. The server *also* configures an email-OTP second factor (`otpOptions.sendOTP`), but there is no UI here to request or verify an emailed 2FA code. Email 2FA is configured-but-unused by the current `/auth/2fa` page; add a `verifyOTP` action and a "send code by email" control if you want it reachable.
</Callout>

<Callout type="info">
`/auth/2fa` (`PAGE_ROUTES.TWO_FACTOR`) is included in `AUTH_ROUTE_PREFIXES` (`apps/web/lib/routes.ts`), so the edge `middleware.ts` gate treats it like the other auth pages: reachable without a session cookie. The redirect for a fully-authenticated user visiting it directly happens separately, in `apps/web/app/[locale]/auth/layout.tsx`, which calls the DB-verified `getServerSession()` (i.e. `auth.api.getSession()`) and sends them to `/org` — the edge middleware itself never calls `getSession()`, it only checks cookie presence.
</Callout>

## End-to-end sequence

```mermaid
sequenceDiagram
    actor User
    participant SignIn as SignInForm
    participant BA as Better Auth<br/>/api/auth/*
    participant Client as twoFactorClient
    participant TFA as /auth/2fa
    participant Org as /org

    User->>SignIn: Submit password (2FA-enabled account)
    SignIn->>BA: signIn.email({...})
    BA-->>Client: "two factor required" (no full session yet)
    Client->>TFA: onTwoFactorRedirect → window.location = "/auth/2fa"
    User->>TFA: Enter 6-digit TOTP code
    TFA->>BA: verifyTwoFactorAction → auth.api.verifyTOTP({ code })
    BA->>BA: validate against TwoFactor.secret, create Session
    BA-->>TFA: ok
    TFA->>Org: router.push("/org") + refresh()
```
