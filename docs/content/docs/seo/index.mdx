`@repo/seo` provides site-wide metadata, JSON-LD structured data, and is wired into `apps/web`'s root layout, `sitemap.ts`, and `robots.ts`.

## Site config

`configureSeo()` sets a single, module-level `SiteConfig` that the rest of the package reads via `getSiteConfig()`:

```ts
// packages/seo/config.ts
export interface SiteConfig {
  name: string;
  description: string;
  url: string;
  ogImage?: string;
  locale?: string;
  twitterHandle?: string;
  author?: { name: string; url?: string };
  links?: { twitter?: string; github?: string };
}
```

The web app configures it once in `apps/web/lib/seo-config.ts`:

```ts
import { configureSeo, type SiteConfig } from "@repo/seo";
import { env } from "@/lib/env";

export const siteConfig: SiteConfig = {
  name: env.NEXT_PUBLIC_APP_NAME,
  description: `${env.NEXT_PUBLIC_APP_NAME} — multi-organization SaaS platform.`,
  url: env.NEXT_PUBLIC_APP_URL,
  ogImage: "/og-image.png",
  locale: "en_US",
};

configureSeo(siteConfig);
```

Identity comes entirely from `NEXT_PUBLIC_APP_NAME` and `NEXT_PUBLIC_APP_URL` — the optional `twitterHandle`, `author`, and `links` fields on `SiteConfig` are left unset, since the app has no per-customer values to put there.

`apps/web/app/[locale]/layout.tsx` imports this module (for its side effect) before calling anything else in `@repo/seo`.

## Default metadata

`getDefaultMetadata()` builds a Next.js `Metadata` object from the site config: title template, description, Open Graph, Twitter card, `robots` (full index/follow + Googlebot directives), and a canonical alternate. It's used directly as the root layout's `metadata` export:

```ts
// apps/web/app/[locale]/layout.tsx
export const metadata = getDefaultMetadata();
```

> `keywords` is currently hardcoded to a generic list (`"blog", "technology", "development", ...`) — update `packages/seo/metadata.ts` if you want keywords tailored to your product.

## Structured data (JSON-LD)

The `JsonLd` component renders an escaped `application/ld+json` script tag. Exactly two schema generators exist today, both rendered in the root layout:

```tsx
import { generateOrganizationSchema, generateWebSiteSchema, JsonLd } from "@repo/seo";

<JsonLd code={generateOrganizationSchema()} />
<JsonLd code={generateWebSiteSchema()} />
```

- **`generateOrganizationSchema()`** — `Organization` schema from `SiteConfig` (name, url, logo, a generic `ContactPoint`). `sameAs` reads `links.twitter`/`links.github`, but the app's `siteConfig` sets no `links`, so it's always an empty array.
- **`generateWebSiteSchema()`** — `WebSite` schema with a `SearchAction` pointing at `/search?q={search_term_string}`.

<Callout type="warn">
The JSON-LD `SearchAction` targets `/search`, but the app has no `/search` route. Remove or replace that `potentialAction` before relying on sitelinks search box rich results.
</Callout>

To add another schema type (Article, FAQPage, etc.), add a generator function to `packages/seo/schemas.tsx` following the same pattern — typed against `schema-dts`, reading from `getSiteConfig()` — and render it with the same `JsonLd` component. None of these exist yet; add them when you actually have the page type to back them (e.g. don't add `Product` schema without product pages).

## Sitemap and robots

`apps/web/app/sitemap.ts` currently returns a single static entry for the homepage — there's no dynamic route enumeration (no blog/CMS in this app to enumerate). `apps/web/app/robots.ts` disallows `/api/`, `/auth/`, `/user/`, `/_next/`, `/private/` for all crawlers plus a Googlebot-specific rule, and points `sitemap`/`host` at `siteConfig.url`.

<Callout type="info">
`/private/` is listed in `robots.ts` but unused — the app has no `/private` route.
</Callout>
