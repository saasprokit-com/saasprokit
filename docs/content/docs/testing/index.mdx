## Test Strategy

This project uses two levels of testing:

| Type | Tool | Location | Status |
|------|------|----------|--------|
| **E2E Tests** | Playwright | `apps/web/e2e/` | **56** cases across 27 files — see [E2E Tests](/docs/testing/e2e-tests) |
| **Unit Tests** | Vitest | `@repo/auth`, `apps/web`, `@repo/database` | See the file list on [Unit Tests](/docs/testing/unit-tests) — do not treat a single total as the source of truth |
| **Integration Tests** | — | — | Not started |

`pnpm test` (`turbo test`) runs all three unit packages because `@repo/database` has a `test` script.

## Running Tests

### E2E Tests (Playwright)

```bash
# Run all E2E tests
pnpm --filter app test:e2e

# Run with browser UI
pnpm --filter app test:e2e:ui

# Run a specific test file
pnpm --filter app test:e2e -- --grep "Sign In"

# Run a specific folder
pnpm --filter app test:e2e -- e2e/payment
```

### Unit Tests (Vitest)

```bash
# Run all unit tests
pnpm test

# Run tests for a specific package
pnpm --filter @repo/auth test
pnpm --filter app test
pnpm --filter @repo/database test

# Run in watch mode
pnpm --filter @repo/auth test -- --watch

# Run a specific test by name (Vitest: --testNamePattern / -t, not --grep)
pnpm --filter @repo/auth test -- --testNamePattern "canOrg"
```

## How E2E is wired

Four Playwright projects in `apps/web/playwright.config.ts`:

| Project | Matches | Depends on |
| --- | --- | --- |
| `auth-setup` | `setup/auth.setup.ts` — signs in, writes `e2e/.auth/user.json` | — |
| `org-setup` | `setup/org.setup.ts` | `auth-setup` |
| `no-auth` | `(public\|auth)/*.spec.ts` — no login | — |
| `authenticated` | `(account\|admin\|dashboard\|members\|payment)/*.spec.ts` | `auth-setup`, `org-setup` |

Local infra: `docker compose -f docker-compose.e2e.yml up` (Postgres on **5433**, Maildev). CI (`.github/workflows/e2e.yml`) is gated on the `e2e` PR label. Details: [E2E Tests](/docs/testing/e2e-tests).
